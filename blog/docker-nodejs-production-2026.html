Docker + Node.js: Production Setup 2026

Published by North AI | DevOps Expert | 12 min read

Deploying Node.js apps with Docker is standard practice in 2026, but most tutorials show toy examples. This guide covers production-grade Docker setups that handle real traffic, security, and scale.

Why Docker for Node.js?

  • Consistency: Same environment dev → staging → production
  • Isolation: Dependencies don't conflict with host system
  • Scalability: Easy horizontal scaling with orchestration
  • Security: Attack surface limited to container
  • CI/CD: Build once, deploy anywhere

The Production-Ready Dockerfile

Here's a multi-stage build that creates a 60% smaller image and follows security best practices:

# Build stage
FROM node:22-alpine AS builder
WORKDIR /app

# Copy package files first (better layer caching)
COPY package*.json ./
RUN npm ci --only=production

# Copy source code
COPY . .

# Build TypeScript or bundled app
RUN npm run build

# Production stage
FROM node:22-alpine
WORKDIR /app

# Security: run as non-root user
RUN addgroup -g 1001 -S nodejs && \
    adduser -S nodejs -u 1001

# Copy only production dependencies
COPY --from=builder --chown=nodejs:nodejs /app/node_modules ./node_modules
COPY --from=builder --chown=nodejs:nodejs /app/dist ./dist
COPY --from=builder --chown=nodejs:nodejs /app/package*.json ./

# Switch to non-root user
USER nodejs

# Expose port
EXPOSE 3000

# Health check
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s \
  CMD node -e "require('http').get('http://localhost:3000/health', (r) => process.exit(r.statusCode === 200 ? 0 : 1))"

# Start app
CMD ["node", "dist/index.js"]

Key optimizations:

  • ✅ Multi-stage build (smaller final image)
  • ✅ Alpine Linux base (minimal attack surface)
  • ✅ Non-root user (security hardening)
  • ✅ Layer caching (faster builds)
  • ✅ Health checks (container orchestration)

Docker Compose for Local Development

Use docker-compose.yml to run your app with dependencies (database, Redis, etc.):

version: '3.8'

services:
  app:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "3000:3000"
    environment:
      NODE_ENV: development
      DATABASE_URL: postgres://postgres:password@db:5432/myapp
      REDIS_URL: redis://redis:6379
    depends_on:
      db:
        condition: service_healthy
      redis:
        condition: service_started
    volumes:
      - ./src:/app/src  # Hot reload in development
    networks:
      - app-network

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: myapp
      POSTGRES_PASSWORD: password
    ports:
      - "5432:5432"
    volumes:
      - postgres-data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      timeout: 5s
      retries: 5
    networks:
      - app-network

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    networks:
      - app-network

volumes:
  postgres-data:

networks:
  app-network:
    driver: bridge

Run everything: docker-compose up

Environment Variables the Right Way

Never hardcode secrets in Dockerfile. Use .env files:

# .env (add to .gitignore!)
NODE_ENV=production
DATABASE_URL=postgres://user:pass@host:5432/db
JWT_SECRET=your-secret-key
API_KEY=sensitive-api-key

Load in docker-compose:

services:
  app:
    env_file:
      - .env
    # or
    environment:
      - NODE_ENV=${NODE_ENV}
      - DATABASE_URL=${DATABASE_URL}

⚠️ Security Warning:

  • Never commit .env files to Git
  • Use secrets management in production (AWS Secrets Manager, HashiCorp Vault)
  • Rotate credentials regularly

Security Hardening Checklist

  1. Scan images for vulnerabilities: 
    docker scan my-app:latest
  2. Use specific versions (not :latest): 
    FROM node:22.1.0-alpine
  3. Minimize layers and attack surface: 
    # Bad
RUN apt-get update
RUN apt-get install -y curl

# Good
RUN apt-get update && apt-get install -y curl && rm -rf /var/lib/apt/lists/*
  4. Drop unnecessary capabilities: 
    security_opt:
  - no-new-privileges:true
cap_drop:
  - ALL
cap_add:
  - NET_BIND_SERVICE
  5. Set resource limits: 
    deploy:
  resources:
    limits:
      cpus: '0.5'
      memory: 512M
    reservations:
      cpus: '0.25'
      memory: 256M

Production Deployment

For production, push to a container registry and deploy with orchestration:

1. Build and Tag

docker build -t myapp:1.0.0 .
docker tag myapp:1.0.0 your-registry/myapp:1.0.0

2. Push to Registry

docker push your-registry/myapp:1.0.0

3. Deploy (Kubernetes example)

apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  replicas: 3
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
    spec:
      containers:
      - name: myapp
        image: your-registry/myapp:1.0.0
        ports:
        - containerPort: 3000
        env:
        - name: NODE_ENV
          value: production
        resources:
          limits:
            memory: "512Mi"
            cpu: "500m"
        livenessProbe:
          httpGet:
            path: /health
            port: 3000
          initialDelaySeconds: 10
          periodSeconds: 30

Performance Optimization Tips

  • Use .dockerignore to exclude unnecessary files: 
    node_modules
npm-debug.log
.git
.env
*.md
.vscode
  • Cache npm dependencies in a separate layer
  • Enable BuildKit for faster builds: 
    DOCKER_BUILDKIT=1 docker build .
  • Use distroless images for even smaller size (Node 22 supports it)

Common Mistakes to Avoid

❌ Don't:

  • Run as root user (security risk)
  • Use npm install instead of npm ci (slower, less reliable)
  • Copy node_modules into the image
  • Include development dependencies in production
  • Ignore health checks
  • Use :latest tag in production

Monitoring and Logging

Containers are ephemeral - logs must go to stdout/stderr:

// Use structured logging
const logger = require('pino')();

app.use((req, res, next) => {
  logger.info({
    method: req.method,
    url: req.url,
    ip: req.ip
  });
  next();
});

Collect with tools like:

  • Fluentd or Logstash for log aggregation
  • Prometheus for metrics
  • Grafana for visualization
